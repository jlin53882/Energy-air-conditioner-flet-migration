# 工作區狀態失效矩陣

本文件定義使用者操作後，各畫面的**輸入**、**結果**與**圖表**應保留或失效。
對應的回歸測試位於 `tests/test_integration_hardening.py`；修改任何一列行為時，
必須同時更新本文件與測試。

## 1. 名詞

- **輸入**：欄位數值、欄位單位、下拉選單與模式選擇（例如錶壓／絕對壓）。
- **結果**：結果卡、關鍵數值、結構化表格與原始文字。
- **圖表**：P-h、T-s、冷凍循環 P-h、濕空氣線圖。
- **失效**：清除結果，並以狀態列「輸入已變更」提示需要重新計算；不得繼續顯示舊數值。
- **只改表示方式的操作**：欄位單位選單、錶壓 ↔ 絕對壓切換。這些操作會換算欄位數值，
  但實際物理量不變，因此不使結果失效。

## 2. 矩陣

| 事件 | 輸入 | 結果 | 圖表 |
|---|---|---|---|
| 切換到其他頁面再回來（A → B → A） | 保留 | 保留 | 保留 |
| P-h 與 T-s 兩個路由互切 | 保留 | 失效 | 清除（圖表種類已改變） |
| 同一頁內切換分析項目 | 保留 | 失效 | 隱藏 |
| 修改會影響計算的輸入（數值、流體、Reference State、模式選項） | 保留 | 失效 | 隱藏 |
| 修改欄位單位 | 數值換算為同一個實際值 | 保留 | 保留 |
| 錶壓 ↔ 絕對壓切換 | 數值換算為同一個實際壓力，單位維持同尺度 | 保留 | 保留 |
| 修改海拔（錶壓模式） | 自動計算大氣壓力；錶壓讀值保留 | 失效 | 隱藏 |
| 修改大氣壓力（錶壓模式） | 錶壓讀值保留，計算時重新換算絕對壓 | 失效 | 隱藏 |
| 切換 SI / Imperial | 保留數值與單位 | 仍有效的結果以新單位重新呈現；已失效的維持失效 | 重繪 |
| 計算失敗 | 保留 | 以錯誤訊息取代 | 隱藏 |

物性查詢頁與分析頁遵守同一套規則。

## 3. 規則說明

### 3.1 單位切換只改呈現

**預期契約**：全域 SI / Imperial 是輸出偏好（presentation preference）。理想做法是保存
canonical 計算結果，切換時只重新格式化，不重新求解 domain。

- 物性查詢頁已符合：保存 SI 結果快照，切換時只重新格式化，不重新查詢。

**目前的過渡期限制**：大多數分析模組只輸出格式化文字，沒有保存可重新格式化的 canonical
結構化結果，因此 `AnalysisModuleAdapter.set_output_unit_system()` 暫時會以目前輸入重新執行
計算（冷凍循環也會重畫 P-h 圖）。這是遷移期的實作限制，不代表單位切換可以改變輸入或
domain 狀態。改為保存 canonical 結果後即可移除這項限制（見 `docs/ui-architecture.md` 對
`structured_from_text()` 的說明）。

即使重新計算，仍必須保證：

- 不修改任何輸入欄位的數值與單位。
- 不使用已修改、尚未送出的輸入覆蓋原結果：修改輸入時結果已經失效（§3.2），切換單位只
  重新計算仍有效的結果。
- 交給 application／domain 的 canonical request 與切換前完全相同。
- 工程結果（COP、壓縮比、壓縮功、冷凍效果、質量流率等）不變，只有顯示單位與格式不同。

每次狀態查詢都會設定並還原 CoolProp reference state，重複求解同一個 request 的結果在
約 1e-9 相對誤差內可能不是逐位元相同；此差異遠小於顯示精度。回歸測試以 1e-7 相對容差
比對工程結果，canonical request 則必須完全相同。

### 3.2 修改輸入使結果失效

`AnalysisModuleAdapter` 在建構時走訪每個分析的輸入控制項（`iter_controls()`），依
`_SEMANTIC_INPUT_EVENTS` 為以下類型加上失效處理，原有的事件處理器會先執行：

| 控制項 | 事件 |
|---|---|
| `TextField` | `on_change` |
| `Dropdown` | `on_select` |
| `Checkbox`、`Switch`、`RadioGroup`、`SegmentedButton` | `on_change` |

判斷標準是**計算語意是否改變**，不是控制項類型：

- **語意輸入**：修改後會改變計算結果的控制項（數值、流體、Reference State、模式選項）。
  必須是上表支援的類型，且位於分析定義的 `input_view` 之下，才會被 `iter_controls()` 找到。
  使用者修改後結果失效。
- **只改表示方式的輸入**：處理器會自行換算欄位數值、使實際物理量維持不變的控制項。欄位
  數值可能改變（例如 0.3 MPa 切成錶壓後顯示 0.198675 MPag），但實際壓力不變，因此不使結果
  失效。包括：
  - 各輸入列的單位選單（`all_entries[...]["unit"]`，adapter 自動排除）。
  - 模組登記在 `presentation_only_controls` 的控制項；`BaseAnalysisModule.apply_pressure_basis`
    會自動登記錶壓／絕對壓切換按鈕。其他這類控制項必須由模組明確登記，不能因為「看起來
    只是 UI」就略過失效處理。

新增輸入控制項時：

1. 若會改變計算語意，確認類型在 `_SEMANTIC_INPUT_EVENTS` 內且放在 `input_view` 之下。
2. 若要使用未支援的 Flet 輸入類型（例如 `Slider`），必須同步擴充 `_SEMANTIC_INPUT_EVENTS`
   與 `tests/test_integration_hardening.py` 的契約測試；該檔另有測試確保正式分析頁沒有使用
   未支援的輸入類型。
3. 若只改表示方式且處理器會維持相同物理量，登記到 `presentation_only_controls`。
4. 以按鈕代替使用者填值的捷徑（例如 `BaseAnalysisModule.create_fluid_row` 的常用冷媒按鈕）
   不是語意輸入類型；它填入欄位後必須呼叫該欄位目前的 `on_change`，讓 adapter 的失效處理照常執行。

### 3.3 Reference State

每一頁使用自己的 Reference State，不跟隨其他頁面：

| 畫面 | 來源 |
|---|---|
| 物性查詢 | 物性查詢頁的選單 |
| 熱力圖（P-h、T-s） | 熱力圖頁的選單 |
| 冷凍循環 | 冷凍循環頁的選單（預設 Auto） |
| 冷凝器 Exergy | 冷凝器 Exergy 頁的選單（預設 Auto） |
| 壓縮機綜合分析範例 | 依流體決定（冷媒 ASHRAE、水 Default）；結果只含效率、功與㶲破壞等狀態差值，與 reference state 無關，因此不提供選單 |
| 飽和性質 | 飽和性質頁的選單（預設 Auto）；只改變狀態點的焓、熵，飽和溫度／壓力與潛熱不變 |
| 過熱度／過冷度判讀 | 過熱／過冷頁的選單（預設 Auto）；只改變狀態點的焓、熵，過熱度、過冷度與飽和溫度不變 |

- 任何一頁的計算都不得改變其他頁面之後計算所用的 policy。
- 只由狀態差值構成的結果（COP、壓縮功、冷凝器 Exergy 平衡、壓縮機範例）切換
  ASHRAE / IIR / NBP 後數值必須相同；焓、熵等絕對值則依所選基準改變。

### 3.4 錶壓與絕對壓

依 `docs/hvac-ui-domain-contract.md`：錶壓模式使用錶壓單位（`kPag`、`psig`…），
絕對壓模式使用絕對單位；切換時換算數值以維持同一個實際壓力；大氣壓力無法解析時
維持原模式並提示。適用於飽和性質（已知壓力）、過熱度／過冷度判讀、壓縮比與冷凝器 Exergy。

錶壓模式顯示「海拔高度（選填）」與「大氣壓力」兩個欄位：

- 大氣壓力預設為標準大氣壓 101.325 kPa。
- 填入海拔時，依共用濕空氣服務的標準大氣公式自動計算大氣壓力；清空海拔時恢復
  101.325 kPa；海拔無效時提示錯誤，不改動大氣壓力。
- 大氣壓力欄位仍可手動修改。
- 大氣壓力改變時保留使用者輸入的錶壓讀值（現場儀表讀到的是錶壓），計算時才以新的
  大氣壓力換算絕對壓。

### 3.5 圖表生命週期

- 每個圖表面板持有一個長期存在的 figure；重繪時清除後重畫，不建立新 figure、
  不累積舊資料序列或標註點。
- 計算失敗、結果失效或切換分析項目時隱藏圖表；下次成功計算時重畫。
- 熱力圖路由重新進入同一種圖表時不清除已繪製的圖。
